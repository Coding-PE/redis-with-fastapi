# Redis 모니터링 기초 (INFO, MONITOR, SLOWLOG)

> 강의노트 Ch.07 — Redis 운영 / 모니터링 기초 (INFO, MONITOR, SLOWLOG)

---

## 1. INFO — 서버 상태 조회

```bash
# 전체 정보 조회
127.0.0.1:6379> INFO

# 섹션별 조회
127.0.0.1:6379> INFO server       # 서버 기본 정보
127.0.0.1:6379> INFO clients      # 클라이언트 연결 정보
127.0.0.1:6379> INFO memory       # 메모리 사용 현황
127.0.0.1:6379> INFO stats        # 요청 통계
127.0.0.1:6379> INFO persistence  # 영속성 상태
127.0.0.1:6379> INFO replication  # 복제 상태
127.0.0.1:6379> INFO keyspace     # 데이터베이스별 키 현황
127.0.0.1:6379> INFO commandstats # 명령어별 호출 통계
```

### 주요 항목

```bash
# INFO server — 서버 기본 정보
127.0.0.1:6379> INFO server
# redis_version:7.2.0
# uptime_in_seconds:86400
# uptime_in_days:1

# INFO clients — 클라이언트 연결 정보
127.0.0.1:6379> INFO clients
# connected_clients:10
# blocked_clients:0

# INFO memory — 메모리 사용 현황
127.0.0.1:6379> INFO memory
# used_memory_human:2.50M
# used_memory_peak_human:3.10M
# maxmemory_human:256.00M
# maxmemory_policy:noeviction
# mem_fragmentation_ratio:1.2    ← 1.0~1.5 정상, 높을수록 단편화 의심

# INFO stats — 요청 통계 및 캐시 히트율
127.0.0.1:6379> INFO stats
# total_commands_processed:12345
# instantaneous_ops_per_sec:100
# keyspace_hits:9800
# keyspace_misses:200
# 캐시 히트율 = 9800 / (9800 + 200) × 100 = 98%

# INFO keyspace — 키 현황
127.0.0.1:6379> INFO keyspace
# db0:keys=10000,expires=8500,avg_ttl=86400000,subexpiry=0

# INFO commandstats — 명령어별 호출 통계
127.0.0.1:6379> INFO commandstats
# cmdstat_get:calls=100000,usec=120000,usec_per_call=1.20
# cmdstat_set:calls=50000,usec=75000,usec_per_call=1.50
# cmdstat_hget:calls=30000,usec=42000,usec_per_call=1.40
```

## 2. MONITOR — 실시간 명령어 감시

실습은 **터미널 창 2개** 필요합니다.

```bash
# 터미널 A — MONITOR 실행
127.0.0.1:6379> MONITOR
# OK

# 터미널 B — 명령어 실행
127.0.0.1:6379> SET user:1 "Alice"
127.0.0.1:6379> GET user:1

# 터미널 A — 실시간 출력
# 1717200001.123456 [0 127.0.0.1:12345] "SET" "user:1" "Alice"
# 1717200001.234567 [0 127.0.0.1:12345] "GET" "user:1"
```

> ⚠️ 운영 환경에서는 매우 짧게만 사용하고 반드시 `Ctrl+C`로 종료하세요.

## 3. SLOWLOG — 느린 명령어 찾기

```bash
# 기준 시간 확인 (마이크로초)
127.0.0.1:6379> CONFIG GET slowlog-log-slower-than
# 1) "slowlog-log-slower-than"
# 2) "10000"   ← 10ms 이상 걸린 명령어 기록 (기본값)

# 최대 보관 개수 확인
127.0.0.1:6379> CONFIG GET slowlog-max-len
# 1) "slowlog-max-len"
# 2) "128"

# 기준 시간 변경
127.0.0.1:6379> CONFIG SET slowlog-log-slower-than 5000   # 5ms로 변경

# 실습용 — 기준을 0으로 낮춰 모든 명령어 기록
127.0.0.1:6379> CONFIG SET slowlog-log-slower-than 0

# 명령어 실행
127.0.0.1:6379> SET slowlog:test "hello"

# SLOWLOG 조회
127.0.0.1:6379> SLOWLOG GET 3
# 1) 1) (integer) 5           ← 로그 ID
#    2) (integer) 1717200001  ← 실행 시각 (Unix 타임스탬프)
#    3) (integer) 8           ← 실행 시간 (마이크로초)
#    4) 1) "SET"              ← 명령어
#       2) "slowlog:test"
#       3) "hello"
#    5) "127.0.0.1:12345"    ← 클라이언트 IP:포트
#    6) ""                    ← 클라이언트 이름

# SLOWLOG 개수 확인
127.0.0.1:6379> SLOWLOG LEN

# SLOWLOG 초기화
127.0.0.1:6379> SLOWLOG RESET

# 실습 후 기준값 원복
127.0.0.1:6379> CONFIG SET slowlog-log-slower-than 10000
```

## 4. 실무 적용 — 성능 문제 진단 절차

```bash
# 1. 현재 OPS 및 연결 수 확인
127.0.0.1:6379> INFO stats
127.0.0.1:6379> INFO clients

# 2. 메모리 상태 확인
127.0.0.1:6379> INFO memory

# 3. 느린 명령어 확인
127.0.0.1:6379> SLOWLOG GET 10

# 4. 명령어별 호출 통계 확인
127.0.0.1:6379> INFO commandstats

# 5. 실시간 명령어 흐름 확인 (짧게)
127.0.0.1:6379> MONITOR
```
