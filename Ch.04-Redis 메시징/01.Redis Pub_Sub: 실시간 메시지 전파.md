# Redis Pub/Sub 명령어 모음

> 강의노트 Ch.04 — Redis 메시징 / Pub/Sub: 실시간 메시지 전파

---

## 실습 준비

Pub/Sub 실습은 **터미널 창을 최소 2개** 열어야 합니다.

| 터미널 | 역할 |
| --- | --- |
| 터미널 A | 구독자 (SUBSCRIBE) |
| 터미널 B | 발행자 (PUBLISH) |

각 터미널에서 Redis CLI 접속:

```bash
docker exec -it my-redis redis-cli --raw
```

---

## 1. SUBSCRIBE / PUBLISH / UNSUBSCRIBE

```bash
# 터미널 A — SUBSCRIBE: 채널 구독
127.0.0.1:6379> SUBSCRIBE notifications
# Reading messages... (press Ctrl-C to quit or any key to type command)
# 1) "subscribe"
# 2) "notifications"
# 3) (integer) 1   ← 현재 구독 중인 채널 수

# 터미널 B — PUBLISH: 메시지 발행
127.0.0.1:6379> PUBLISH notifications "message"
# (integer) 1   ← 메시지를 수신한 구독자 수

# 터미널 A — 수신 결과
# 1) "message"
# 2) "notifications"   ← 채널명
# 3) "message"         ← 메시지 내용

# 터미널 A — UNSUBSCRIBE: 채널 구독 해제
127.0.0.1:6379> UNSUBSCRIBE notifications
# 1) "unsubscribe"
# 2) "notifications"
# 3) (integer) 0   ← 현재 구독 중인 채널 수
```

---

## 2. PSUBSCRIBE — 패턴으로 채널 구독

```bash
# 터미널 A — order: 로 시작하는 모든 채널 구독
127.0.0.1:6379> PSUBSCRIBE order:*
# 1) "psubscribe"
# 2) "order:*"
# 3) (integer) 1

# 터미널 B — 다양한 order 채널에 발행
127.0.0.1:6379> PUBLISH order:created "order created"
127.0.0.1:6379> PUBLISH order:payment "payment complete"
127.0.0.1:6379> PUBLISH order:shipping "shipping start"

# 터미널 A — 수신 결과
# 1) "pmessage"
# 2) "order:*"          ← 매칭된 패턴
# 3) "order:created"    ← 실제 채널명
# 4) "order created"    ← 메시지 내용

# PUNSUBSCRIBE — 패턴 구독 해제
127.0.0.1:6379> PUNSUBSCRIBE order:*
```

---

## 3. PUBSUB — 채널 상태 조회

```bash
# 현재 활성 채널 목록 (구독자가 1명 이상인 채널)
127.0.0.1:6379> PUBSUB CHANNELS
# 1) "notifications"
# 2) "order:created"

# 패턴으로 필터링
127.0.0.1:6379> PUBSUB CHANNELS order:*
# 1) "order:created"

# 채널별 구독자 수 조회
127.0.0.1:6379> PUBSUB NUMSUB notifications order:created
# 1) "notifications"
# 2) (integer) 1
# 3) "order:created"
# 4) (integer) 1

# 패턴 구독 수 확인 (PSUBSCRIBE로 구독한 경우)
127.0.0.1:6379> PUBSUB NUMPAT
# (integer) 1   ← 현재 활성 패턴 구독 수
```

---

## 4. 실무 활용 예시

```bash
# 실시간 알림
127.0.0.1:6379> SUBSCRIBE notifications:user:1001          # 알림 서버
127.0.0.1:6379> PUBLISH notifications:user:1001 "주문이 접수되었습니다."  # 주문 서비스

# 채팅
127.0.0.1:6379> SUBSCRIBE chat:room:100
127.0.0.1:6379> PUBLISH chat:room:100 "안녕하세요!"

# Cache Invalidation — 여러 서버에 캐시 무효화 신호 전파
127.0.0.1:6379> SUBSCRIBE cache:invalidation               # 각 서버가 구독
127.0.0.1:6379> PUBLISH cache:invalidation "product:500"   # DB 업데이트 시 발행
```
