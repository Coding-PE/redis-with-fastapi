# Redis Streams 명령어 모음

> 강의노트 Ch.04 — Redis 메시징 / Redis Streams: 메시지 저장과 스트림 처리

---

## 1. 기본 명령어

```bash
# XADD — 메시지 추가 (* 는 ID 자동 생성)
127.0.0.1:6379> XADD orders * event "order_created" user_id "1001" amount "50000"
# "1735689600000-0"   ← 자동 생성된 Entry ID

127.0.0.1:6379> XADD orders * event "order_paid" user_id "1001" amount "50000"
# "1735689600001-0"

# MAXLEN — 스트림 크기 제한과 동시에 추가 (~ = 근사값 트리밍, 실무 권장)
127.0.0.1:6379> XADD orders MAXLEN ~ 1000 * event "order_created" user_id "1001"
# "1735689600000-0"

# XLEN — 메시지 수 확인
127.0.0.1:6379> XLEN orders
# (integer) 2

# XRANGE — ID 범위로 조회 (- = 최솟값, + = 최댓값)
127.0.0.1:6379> XRANGE orders - +
# 1) 1) "1735689600000-0"
#    2) 1) "event"
#       2) "order_created"
#       3) "user_id"
#       4) "1001"
#       5) "amount"
#       6) "50000"

# 특정 시간 범위 조회
127.0.0.1:6379> XRANGE orders 1735689600000-0 1735689700000-0

# XREVRANGE — 역순으로 최신 3개 조회
127.0.0.1:6379> XREVRANGE orders + - COUNT 3

# XREAD — 처음부터 전체 읽기 (0 = 처음부터)
127.0.0.1:6379> XREAD COUNT 10 STREAMS orders 0
# 1) 1) "orders"
#    2) 1) 1) "1735689600000-0"
#          2) 1) "event"
#             2) "order_created"
#             3) "user_id"
#             4) "1001"
#             5) "amount"
#             6) "50000"

# 특정 ID 이후 메시지만 읽기
127.0.0.1:6379> XREAD COUNT 10 STREAMS orders 1735689600000-0

# 블로킹 모드 — 새 메시지 올 때까지 무한 대기 ($ = 이후 새로 추가되는 메시지)
127.0.0.1:6379> XREAD BLOCK 0 STREAMS orders $
```

## 2. Consumer Group

```bash
# XGROUP CREATE — Consumer Group 생성
# $ = 이후 새 메시지부터 처리 / 0 = 처음부터 처리 / MKSTREAM = 스트림 없으면 자동 생성
127.0.0.1:6379> XGROUP CREATE orders order-processors $ MKSTREAM
# OK

127.0.0.1:6379> XGROUP CREATE orders order-processors 0
# OK

# XREADGROUP — Consumer Group에서 메시지 읽기
# > = 아직 다른 Consumer에게 전달되지 않은 새 메시지
127.0.0.1:6379> XREADGROUP GROUP order-processors consumer-1 COUNT 1 STREAMS orders >
# 1) 1) "orders"
#    2) 1) 1) "1735689600002-0"
#          2) 1) "event"
#             2) "order_created"

# XACK — 메시지 처리 완료 (PEL에서 제거)
127.0.0.1:6379> XACK orders order-processors 1735689600002-0
# (integer) 1   ← ACK 처리된 메시지 수

# XPENDING — 처리 중인(미확인) 메시지 조회
127.0.0.1:6379> XPENDING orders order-processors - + 10
# 1) 1) "1735689600000-0"   ← Entry ID
#    2) "consumer-1"         ← 가져간 Consumer
#    3) (integer) 5000       ← 대기 시간 (ms)
#    4) (integer) 1          ← 전달 횟수
```

> ⚠️ `XACK`를 보내지 않으면 메시지는 PEL(Pending Entry List)에 남습니다. 장애 복구 시 `XPENDING`으로 미처리 메시지를 확인하고 `XCLAIM`으로 재할당하세요.

## 3. 스트림 관리

```bash
# XTRIM — 스트림 크기 제한
127.0.0.1:6379> XTRIM orders MAXLEN 1000
# (integer) 0   ← 삭제된 메시지 수

# XTRIM 근사값 트리밍 (실무 권장)
127.0.0.1:6379> XTRIM orders MAXLEN ~ 1000

# XINFO STREAM — 스트림 기본 정보
127.0.0.1:6379> XINFO STREAM orders
# 1) "length"
# 2) (integer) 2
# 3) "first-entry"
# 4) ...

# XINFO GROUPS — Consumer Group 정보
127.0.0.1:6379> XINFO GROUPS orders
# 1) 1) "name"
#    2) "order-processors"
#    3) "consumers"
#    4) (integer) 2
#    5) "pending"
#    6) (integer) 0
```

## 4. 실무 활용 예시

```bash
# 로그 수집
127.0.0.1:6379> XADD app:logs * level "ERROR" service "order" message "DB connection failed"
127.0.0.1:6379> XADD app:logs * level "INFO"  service "payment" message "Payment processed"

127.0.0.1:6379> XGROUP CREATE app:logs log-collectors 0
127.0.0.1:6379> XREADGROUP GROUP log-collectors collector-1 COUNT 100 STREAMS app:logs >
127.0.0.1:6379> XACK app:logs log-collectors 1735689600000-0

# 이벤트 기반 작업 큐
127.0.0.1:6379> XADD order:events * type "order_created" order_id "1001" user_id "5001"

127.0.0.1:6379> XGROUP CREATE order:events order-workers 0
127.0.0.1:6379> XREADGROUP GROUP order-workers worker-1 COUNT 1 STREAMS order:events >
127.0.0.1:6379> XACK order:events order-workers 1735689600000-0

# 서비스 간 이벤트 전파 — 여러 서비스가 동일 스트림을 독립적으로 처리
127.0.0.1:6379> XADD inventory:events * product_id "500" action "decrease" quantity "1"

127.0.0.1:6379> XGROUP CREATE inventory:events notification-service 0   # 알림 서비스
127.0.0.1:6379> XGROUP CREATE inventory:events stats-service 0          # 통계 서비스
```
