## 1. MULTI / EXEC / DISCARD

```bash
# MULTI — 트랜잭션 시작
127.0.0.1:6379> MULTI
# OK
127.0.0.1:6379(TX)> SET balance 1000
# QUEUED
127.0.0.1:6379(TX)> DECRBY balance 200
# QUEUED
127.0.0.1:6379(TX)> GET balance
# QUEUED
127.0.0.1:6379(TX)> EXEC
# 1) OK
# 2) (integer) 800
# 3) "800"

# DISCARD — 트랜잭션 취소 (큐 비우기)
127.0.0.1:6379> MULTI
# OK
127.0.0.1:6379(TX)> SET balance 5000
# QUEUED
127.0.0.1:6379(TX)> DISCARD
# OK
127.0.0.1:6379> GET balance
# "800"   ← 취소되어 기존 값 유지
```

## 2. 롤백 없음 확인

```bash
127.0.0.1:6379> SET balance 1000
# OK
127.0.0.1:6379> MULTI
# OK
127.0.0.1:6379(TX)> SET balance 2000
# QUEUED
127.0.0.1:6379(TX)> LPUSH balance a b     # ← 타입 오류 유발
# QUEUED
127.0.0.1:6379(TX)> SET balance 9999
# QUEUED
127.0.0.1:6379(TX)> EXEC
# 1) OK
# 2) (error) WRONGTYPE Operation against a key holding the wrong kind of value
# 3) OK

127.0.0.1:6379> GET balance
# "9999"   ← 2번째 실패해도 3번째는 정상 실행됨 (롤백 없음)
```

## 3. WATCH — 낙관적 락(Optimistic Lock)

WATCH 실습은 **터미널 창 2개** 필요합니다.

```bash
# 터미널 A — WATCH 걸고 트랜잭션 시작
127.0.0.1:6379> SET stock 10
# OK
127.0.0.1:6379> WATCH stock
# OK
127.0.0.1:6379> GET stock
# "10"
127.0.0.1:6379> MULTI
# OK
127.0.0.1:6379(TX)> DECR stock
# QUEUED

# 터미널 B — EXEC 전에 같은 키 변경
127.0.0.1:6379> DECR stock
# (integer) 9

# 터미널 A — EXEC 실행
127.0.0.1:6379(TX)> EXEC
# (nil)   ← WATCH 감지로 트랜잭션 취소
```

> `EXEC`가 `(nil)`을 반환하면 트랜잭션이 취소된 것입니다. 애플리케이션에서 재시도(retry) 로직이 필요합니다.

## 4. 실무 활용 예시

```bash
# 포인트 차감 + 구매 이력 기록을 트랜잭션으로 묶기
127.0.0.1:6379> MULTI
# OK
127.0.0.1:6379(TX)> DECRBY user:1001:point 500
# QUEUED
127.0.0.1:6379(TX)> LPUSH user:1001:history "purchase:item:202"
# QUEUED
127.0.0.1:6379(TX)> EXEC
# 1) (integer) 4500
# 2) (integer) 1
```

## 5. Python(redis-py)에서 MULTI/EXEC

```python
# transaction=True (기본값) — 내부적으로 MULTI/EXEC 자동 적용
pipe = r.pipeline()
pipe.decrby("user:1001:point", 500)
pipe.lpush("user:1001:history", "purchase:item:202")
results = pipe.execute()
# results → [4500, 1]
```
